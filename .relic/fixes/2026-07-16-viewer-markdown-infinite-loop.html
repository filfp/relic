Fix: viewer markdown tabs freeze the page on wrapped inline-code lines

ID: 2026-07-16-viewer-markdown-infinite-loop Date: 2026-07-16 Spec: 012-spec-viewer Status: solved Classification: code-bug

Issue

Opening a spec in the viewer and switching to a markdown tab (spec / plan / tasks) froze the browser tab. Reported while dogfooding the viewer on the relic repo itself — reproduced on most specs' own markdown files.

Impact: any markdown file containing a paragraph line that starts with inline code (a wrapped line like `relic search` continues here…) hard-hangs the renderer. 36 real markdown files in this repo, many affected — the markdown tabs were effectively unusable.

Root Cause

code-bug — in packages/viewer/src/markdown.ts, the paragraph collector's guard excluded any line starting with #, >, |, or a backtick — but the block branches only consume a subset of those (fences need ```, headings need #{1,4} ). A line such as `relic search` … was excluded by the paragraph guard yet consumed by no branch, so the line index never advanced: an infinite loop inside markdownToHtml, ported unnoticed from the retired base.html reader.

Changes

graph LR A[dispatch line] --> B{block start?} B -->|yes| C[block branch consumes] B -->|no| D[paragraph consumes >= 1 line] D --> E[i++ safety fallback]

A single isBlockStart() predicate now mirrors the dispatch order exactly and gates the paragraph loop; every non-blank, non-block line is consumed as paragraph text, and a safety i++ guarantees progress. Verified by rendering all 36 markdown files in this repo (6ms, previously hung).
