Fix: relic validate flags .html files as illegal in html mode

ID: 2026-06-02-validate-illegal-files-html-mode Date: 2026-06-02 Spec: 008-html-spec-mode Status: solved Classification: code-bug

Issue

When a project is configured with "mode": "html", relic scaffold creates a <spec-id>.html file inside each spec directory alongside the four standard files. relic validate does not know about html mode and checks all spec directories against a hard-coded four-file allowlist, causing it to report every .html file as an illegal_files error and set valid: false.

Impact: In html mode projects, relic validate always reports valid: false due to illegal_files errors — even when every spec is perfectly formed. Any CI check or AI workflow command that relies on a clean validate output will be permanently blocked. The output cannot be trusted to surface real issues.

Observed output

{
  "valid": false,
  "illegal_files": [
    { "file": "008-html-spec-mode.html",            "spec": "008-html-spec-mode" },
    { "file": "009-external-spec-integration.html", "spec": "009-external-spec-integration" },
    { "file": "010-prompt-snippet-injection.html",  "spec": "010-prompt-snippet-injection" }
  ]
}

All three .html files are valid, intentional spec documents created by relic scaffold in html mode. None of them are preamble violations.

Root Cause

code-bug — Spec 008's plan explicitly covers this in Phase 7b: "When mode = 'html', permit <spec-id>.html as a legal file in spec folders." Phase 7b was marked blocked at implementation time due to an intersection with specs 005 and 009, and was never completed after the intersection was resolved.

Faulty code — validate.ts line 12 and lines 79–87

// Line 12 — static allowlist, never consulted against mode
const ALLOWED_SPEC_FILES = new Set(["spec.md", "plan.md", "tasks.md", "artifacts.json"]);

// Lines 79–87 — illegal files check ignores mode entirely
if (dirExists(spec.path)) {
  const entries = readdirSync(spec.path);
  for (const entry of entries) {
    if (statSync(join(spec.path, entry)).isFile() && !ALLOWED_SPEC_FILES.has(entry)) {
      illegalFiles.push({ file: entry, spec: spec.id });  // ← html file always flagged
    }
  }
}

The runValidate function never reads config.json. The readMode helper already exists in @relic/utility and is already imported in context.ts — it simply was not wired up in validate.ts.

Proposed Changes

Code change — packages/core/src/commands/validate.ts

Two changes: (1) add readMode to the import from @relic/utility; (2) in the illegal files loop, add a mode-aware exception that allows <spec-id>.html when mode === "html". No other files need changing.

Diff (logical)

// Before — line 3
import { findRelicDir, fileExists, dirExists, readJson, readText, decodeToon } from "@relic/utility";

// After — line 3
import { findRelicDir, fileExists, dirExists, readJson, readText, decodeToon, readMode } from "@relic/utility";


// Before — runValidate, after loadRegistry call (approx line 30)
// (no mode read)

// After — add one line after relicDir is resolved
const mode = readMode(relicDir);


// Before — illegal files check (lines 82–84)
if (statSync(join(spec.path, entry)).isFile() && !ALLOWED_SPEC_FILES.has(entry)) {
  illegalFiles.push({ file: entry, spec: spec.id });
}

// After
const isHtmlSpecFile = mode === "html" && entry === `${spec.id}.html`;
if (statSync(join(spec.path, entry)).isFile() && !ALLOWED_SPEC_FILES.has(entry) && !isHtmlSpecFile) {
  illegalFiles.push({ file: entry, spec: spec.id });
}

Resolved — 2026-06-02

Applied. Two changes in packages/core/src/commands/validate.ts:

  • Added readMode to the import from @relic/utility.
  • Added const mode = readMode(relicDir) after loadRegistry.
  • Added const isHtmlSpecFile = mode === "html" && entry === `${spec.id}.html` and included && !isHtmlSpecFile in the illegal files condition.

Verified: bun run packages/cli-node/src/bin.ts validate now returns "valid": true with an empty illegal_files array on this html mode project. Completes spec 008 Phase 7b.

No spec or shared artifact mutations — no changelog entry required.
