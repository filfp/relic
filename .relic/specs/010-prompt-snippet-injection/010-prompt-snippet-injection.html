Overview

Scope narrowed. This spec covers Track 1 — Snippet injection only. Track 2 (Skill extraction) is 011-skill-extraction.

The 12 prompt templates in templates/prompts/ suffer from static content duplication — the same preamble guard, HTML rules, and inline reader instructions appear verbatim across 6–10 files. A one-line change to any of these blocks requires editing up to 10 files.

This spec introduces a templates/snippets/ directory of named Markdown fragments. Templates reference snippets with <!-- include: relic snippet <name> --> directives resolved by the LLM at runtime via relic snippet <name>. Directives travel verbatim through the build pipeline — no substitution at build time.

Block Classification

Every repeated static block in the current templates — all are snippet candidates (Track 1). Procedural steps are out of scope; see 011-skill-extraction.

Snippet Set

4 snippet files after FR-17 consolidation. Each change touches 1 file instead of up to 7.

~88 lines of duplication eliminated.

Clarify Sessions — Architecture Decisions

All 6 open questions resolved. Architecture finalised. Spec ready for plan phase.

Architecture Reversal — Runtime, Not Build-Time

Fundamental change: Directives are NOT resolved at build time. They travel verbatim in baked templates. The LLM sees the directive and calls relic snippet <name> at runtime. This makes templates self-describing — the LLM reads the directive as an instruction.

Dual Directive Syntax

Both are HTML comments — invisible in GitHub Markdown previews, machine-readable by the LLM.

Snippet Composition

Snippets may include other snippets via nested <!-- include: --> directives. Composition via inclusion only — no {{PLACEHOLDER}} variable substitution.

FR-17 resolved: preamble-guard.md and preamble-guard-extended.md merged into one universal 4-line preamble snippet. The extended variant (stricter language) applied universally. Snippet count reduced from 5 to 4.
