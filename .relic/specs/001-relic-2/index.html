Relic 2.0

Shared project knowledge without workflow ceremony

Relic preserves the current project knowledge used by developers and coding agents. It keeps specification-driven development as a useful practice while removing the mandatory specify, clarify, plan, tasks, and implement pipeline.

Product center: durable shared knowledge is the product; SDD is one way to produce it. Persistence remains developer-owned.

Product surface

SurfaceResponsibility
Central skill Challenge, clarify, review, implement, fix, and persist explicitly approved knowledge.
Knowledge corpus Store the current linked specification, shared, FR, NFR, ADR, and EPIC nodes.
Search Discover canonical content and textual spec artifacts in large repositories.
Frontend Read the exhaustive corpus, graph, artifacts, and maintenance evidence interactively.
CLI Provide only init, install, search, and serve.

Natural development flow

Developer request -> relevant project knowledge -> proportional roast -> requested analysis or code -> validation -> optional developer-approved persistence

No mode selector or second prompt is required. The skill uses the repository map progressively and lets each coding agent choose appropriate native exploration tools.

Knowledge boundary

  • .relic/RELIC.md is the sole topology authority and bootstrap map.
  • Every specification has one canonical semantic index.html.
  • Shared documents and typed records are canonical Markdown with only id required.
  • Other files inside a spec folder are searchable artifacts, not graph nodes.
  • Ordinary relative links create a peer-to-peer web and derived backlinks.
  • Statuses, metadata, and project governance remain project-defined.
  • Git retains superseded history; active Relic knowledge describes the current frontier.

Authority and mutation

Code is evidence of present behavior; documentation captures current intent, contracts, decisions, and structure. Drift is investigated from current evidence. The skill never creates, moves, reconciles, or deletes knowledge silently.

Numeric identities derive from the greatest valid identity currently present in the applicable topology root. Relic keeps no counter, lock, reservation, tombstone, session, manifest, or desired-state engine registry.

Read and safety model

One core read model feeds CLI search, the local API, and the frontend. Malformed, disconnected, duplicated, or broken knowledge remains visible with localized diagnostics whenever it can be read safely.

Canonical HTML is converted to an allowlisted semantic AST. Active content never executes. Artifacts are repository-contained; only passive raster images render inline and all active or textual formats download with restrictive headers.

Deliberately absent

Relic 2.0 contains no constitution, preamble, fixed spec anatomy, Markdown/HTML mode, workflow prompts, validation command, active document, hidden state, generated backlink index, plugin router, or 1.x compatibility layer.
