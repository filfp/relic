Overview

implemented spec-009 2026-05-20 clarified 2026-05-20 implemented 2026-07-02

Enterprise teams maintain FRs, NFRs, BRs, ADRs, User Stories, and Epics in a separate spec repository — owned by PMs, designers, and platform teams. This spec treats that repo as a first-class git submodule of the project monorepo and makes Relic a contributor to it, not just a reader.

Write model (clarified): Relic can create and edit documents in the external spec repo. Git branch+PR is the safety guarantee — Relic commits, the document owner reviews before merge. One hard boundary: Relic must never delete files in the external spec repo. No other write restriction applies.

The external spec repo is the team-wide human-readable layer — PMs and designers read it directly, without access to the code repo. The monorepo pins a specific commit of the spec repo (git submodule); git submodule update --remote distributes the latest to the whole team.

config.external is a flat per-type path map — each document type points to its own directory. No Relic-imposed conventions; existing repo layouts are fully supported.

CLI commands — full surface

Document types — naming in configured directory

Files go into the directory configured for that type. No forced subdirectory structure — the team's layout is respected.

Prompt template changes (6 commands)

Before any main work: validate all external_reads paths → hard stop if any missing → load files. AI workflow commands (clarify, plan) may also edit external spec documents when contracts change; those edits must be committed by the team.

Path traversal (../) outside the configured type directory is rejected as a hard error at relic external link, relic external create, and relic validate.
